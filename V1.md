# V1.md — Definition of done for gutenberg-sync-engines v1

This file is the frozen scope contract for the v1 loop. The loop reads it every
cycle; humans edit it. Rules:

- **An item is DONE when its acceptance commands pass and a fresh-context
  verifier confirms it.** The verifier sees only the diff, this file, and the
  command output — never the executor's narrative.
- **Lane A** items may be completed autonomously (implement, verify, commit to
  the item's worktree branch). **Lane B** items stop at a prepared branch plus
  a written proposal; a human approves before anything merges.
- Scope changes to this file are always Lane B. If an item turns out to need a
  Lane-B surface (see "Escalation triggers"), the loop reclassifies it, parks
  it with a diagnosis, and moves on.
- Progress, attempt counts, and lessons live in `LOOP.md` (the ledger), not
  here.

Scope sources: AGENTS.md's known issues, and the "Open items roll-up
(2026-08-19)" in `docs/engine-comparison.md` — every roll-up item appears
below (as an item, or in out-of-scope with a reason).

## V1 statement

V1 is done when: the known bugs below are fixed; the full e2e suite is green
without retries; the websocket suite carries no skips; the de-rtc
announce/commit inversion's verification debt is discharged;
`composer lint` is clean; a full fuzzer
matrix soak ends with every finding fixed or filed; and every Lane-B item has
a human-approved resolution (landed or explicitly deferred by the human).

## Lane A — autonomous items

### A1. Intent-log: reload on an empty-genesis room strands a block insert

Open bug (found 2026-08-17, pre-existing). After a mid-session reload of one
participant on an empty-genesis room, that participant's next block insert can
stay local forever — the room log never receives the intent. Schedule-dependent:
needs the reload milestone at step 0 on the empty template.

**Acceptance:**

```bash
npm run fuzz -- --combos=intent-log/http-polling --seed-list=6 --steps=14 --profile=concurrency   # passes
node tests/tools/sweep.js 60 400 3      # no oracle violations
npm run test:js                          # includes a new regression test for the stall
npm run fuzz:quick                       # green
```

**Notes:** use `--shrink` and `RTC_FUZZ_LOG_SYNC=1` for diagnosis. If the root
cause lives in the frozen core (`src/engines/intent-log/`), this becomes Lane B
(B2) — the client-side `client.js` replica is additive-editable, the rest is
not.

### A2. E2e flake stabilization

The three known full-suite-load flakes: a save notice, a fixture login
navigation, and `http-only/collaboration-sync-body-size` failing after a
preceding engine-flip suite (reproduced by the yjs suite followed by body-size,
no de-rtc involved). Each spec is green solo; v1 requires the suite green
without leaning on CI retries.

**Acceptance:** 3 consecutive full default-suite runs, retries disabled, all
green:

```bash
npm run test:e2e -- --retries=0    # x3 consecutive, serialized, fresh tests env
```

**Notes:** runs must be serialized with everything else touching the tests env
(never `test:php` in parallel). Fix the specs/fixtures or add real ordering
isolation — do not raise timeouts blindly, and do not mark specs serial-only
without a written reason in the ledger.

### A3. Websocket suite: remove the `test.fixme` skip

`tests/e2e/specs/websocket-only/collaboration-concurrent-typing.spec.ts:50` is
skipped because the peer-relay WS fixture only demonstrates client-merging
engines, and none remains. Re-enable by pointing the suite at the plugin's real
websocket transport (the `wp collaboration sync-server` daemon, as `npm run
rtc:ws` wires it) or by giving the fixture plugin a server lane. A
real-daemon e2e lane is also the stated condition for the websocket
transport to stop being "experimental" — prefer that route.

**Acceptance:**

```bash
grep -rn "fixme" tests/e2e/specs/websocket-only/   # no matches
npm run test:e2e:websocket                          # green, x3 consecutive, retries disabled
```

**Notes:** daemon must bind 0.0.0.0 with the port published
(`curl localhost:8787/health` from the host is the reachability test).
`@y/websocket-server` stays pinned to exactly 0.1.1.

### A4. yjs-server genesis: stripped markup lands in the first rich-text attribute

Plugin-fixable defect (found while scoping the materialization work): genesis
puts a block's whole stripped inner markup into its FIRST rich-text-source
attribute — for `core/image` the `<img …>` markup lands in `caption`.
Self-consistent for byte round-trips but semantically wrong the moment anyone
edits the caption. This is distinct from the framework-blocked materialization
half (B1).

**Acceptance:**

```bash
npm run test:php -- --filter <new genesis rich-text tests>   # image caption seeds empty; <img> not in caption
npm run test:js                                              # green
npm run fuzz:quick                                           # green
```

**Notes:** genesis blocks must keep `isValid: true` (has bitten). Watch the
byte-round-trip property the current behavior accidentally preserves — the fix
must not regress solo save/reload convergence (e2e yjs spec covers it).

## Lane B — human-review items

The loop may investigate, design, and implement these on a worktree branch,
but the result is a proposal (branch + written summary of what changed and
why + verification evidence), never a merge. The human approves, requests
changes, or defers.

### B1. yjs-server materialization fidelity (framework changes)

The framework-blocked half of the materialization-fidelity work:
yjs-server materialization still carries the Phase-2a wrapper
simplification — intent-log's twin was fixed by client-authored save
markup; the yjs path needs the same move in the framework (core-data
owns the Yjs block writer, `applyPostChangesToCRDTDoc`). The recorded
design: write `_wrapper`/`_save` entries into each
block's Y.Map from the same save-markup adapter; the engine's
`to_serializable_block` prefers in-doc entries over genesis wrappers.

**Proposal must include:** the subtree diff kept minimal and clearly bounded;
`cd gutenberg && npm run build` side-effects on tracked files reverted; the
full ladder green (`test:js`, `test:php`, `test:e2e`, `fuzz:quick`); and a
note on what the change implies for upstreaming (upstreaming itself is
human-owned and out of v1).

**Why Lane B:** framework edits change the pinned contract every engine runs
against, and the subtree eventually has to reconcile with upstream Gutenberg —
a judgment call about divergence cost.

### B2. Frozen-surface escalations (standing item)

Any change to: the frozen intent-log core (`src/engines/intent-log/**` except
additive `client.js` work, and its PHP twin), the frozen DE-RTC merge core
(`includes/engines/de-rtc/merge-core.php`), vendored `y-php` /
`automerge-php`, or the SEMANTICS of the frozen test vectors. The loop stops
at a written proposal: the smallest viable change, why no non-frozen
alternative exists, and how cross-language parity is re-certified (both vector
copies regenerated together, conformance suites green).

### B3. Pending-edit UI phase: inline block cards; panel goes summary-only

The validated prototype's decisions are recorded (two verbs
Adopt/Reject, one merged task per block, no version chip, panel becomes
summary-only with resolution at the inline block card). The behavior layer is
done; this is the editor-component UI that replaces the interim review-panel
routing.

**Why Lane B:** product-facing UX. The loop may build it to the prototype's
recorded decisions, but the human judges the result against the prototype
before merge. Verification evidence: Jest for the card lifecycle, an e2e
contested-edit walkthrough, `fuzz:quick` green.

### B4. Commit-cadence dial

Expose de-rtc's commit cadence (currently the settle cycle) as a setting with
the vision's 10-second operating point available. The inversion left it "a
setting away, not an architecture away."

**Why Lane B:** the default is a product decision (pseudo-realtime vs the
vision's cheap-host cadence changes what every de-rtc user experiences). The
proposal should include `save-sync-session` benchmark runs at both defaults.

### B5. Review resolutions over REST

The last mutating transport row: review RESOLUTIONS still ride transport rows.
Moving them to a REST review lane completes the strictest reading of the
transport-is-advisory inversion.

**Why Lane B:** a wire-protocol change (see escalation triggers — protocol
shape changes are Lane B by rule). Small, but it touches the session codec
contract and legacy-client behavior.

### B6. V1 sign-off

Human-only: review the ledger's parked/escalated list, approve or defer each
Lane-B proposal, merge the item branches, and declare v1. Any outward-facing
action (PRs, pushes to shared branches, upstream issues) is human-owned and
never part of the loop.

## Escalation triggers (Lane A → Lane B, automatic)

- The fix requires editing the `gutenberg/` subtree.
- The fix requires editing a frozen surface (see B2).
- The fix changes a wire format, storage row shape, or engine protocol number.
- The fix deletes or weakens an existing test to pass.
- Three failed attempts on one item (park with diagnosis, move on).

## Loop protocol (summary — the loop prompt is authoritative)

- Preflight every cycle: `npm run doctor`; fix or park on environment
  failures — uniform cross-engine timeouts are an environment problem.
- One ledger item per cycle, on branch `loop/<item-id>`, commits with
  `--no-verify`. Side discoveries become new ledger entries, never drive-bys.
- Suites are serialized: never `test:php` while e2e is in flight; one tests
  env consumer at a time.
- Maker is never grader: a fresh-context verifier confirms acceptance before
  an item is marked done.
- Stop rules: acceptance passed → next item; 3 strikes → park; budget
  exhausted → park cleanly; ledger empty → report and stop.
