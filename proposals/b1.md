# B1 — yjs-server materialization fidelity (the framework half)

## The problem

yjs-server materialization carried the Phase-2a wrapper simplification:
the server rebuilds each block's inner HTML from the genesis wrapper
record (or a static default), so anything the genesis didn't capture is
frozen — an alignment class added mid-session never materializes, a
heading level change keeps the old tag, and blocks born in-session get
a guessed default wrapper (or none). intent-log's twin was fixed by
client-authored save markup; the yjs path needed the same move in the
framework, because core-data owns the Yjs block writer.

## What changed

**Subtree — ONE file** (`gutenberg/packages/core-data/src/utils/crdt-blocks.ts`):
every Y.Block now carries a `_save` entry — the block's registered
`save()` output for its CURRENT attributes, rendered with empty inner
blocks (`getSaveContent( blockType, attributes, [] )`):

- written when a block is created in the doc (`createNewYBlock`);
- refreshed in `mergeCrdtBlocks`'s update path whenever a block's
  attributes merge (skipped when unchanged — no extra doc writes);
- excluded from `areBlocksEqual` (doc-side bookkeeping must not make
  every block read as dirty);
- stripped in `deserializeBlockAttributes` so it never reaches editor
  blocks;
- null-safe: unregistered types and throwing `save()` implementations
  simply don't get the entry, and every consumer falls back.

**Plugin — the engine half** (`includes/engines/yjs-server/...`,
stacked on the A4 branch whose selector machinery it reuses):

- the genesis innerHTML decomposition is extracted into one
  `decompose_inner_markup()` (outer wrapper + A4's selector-sourced
  rich-text split), used by genesis and by the new path — one source
  of truth, and the genesis byte-round-trip suite is untouched;
- `to_serializable_block()` prefers a block's `_save` over the genesis
  wrapper record and the static defaults. The mirror's embedded text is
  NEVER read — the live shared rich-text value fills the decomposed
  wrapper (pinned by a stale-text test: a `_save` carrying "STALE TEXT"
  materializes with the real shared text and the new wrapper classes).

## Why this design

The mirror is save-accurate by construction (it IS the block's save
output), covers attribute-derived sub-elements (an image's `<img>`
regenerates when `src` changes), and costs one small string per block
refreshed only on attribute changes. Concurrent-edit safety comes from
never reading the text inside the mirror; a stale mirror (e.g. from an
old client) degrades to at-worst genesis behavior because decomposition
failure falls back.

Legacy compatibility: rooms written before this change have no `_save`
entries and take the old path unchanged; old clients in a mixed session
simply don't refresh mirrors (new clients and the next attribute edit
do).

## Upstreaming note (human-owned, out of v1)

The subtree change is deliberately self-contained and engine-agnostic:
`_save` is generic doc metadata any server-authoritative consumer can
use, and it is invisible to the editor and to equality. Upstream
Gutenberg would likely want (a) a constant instead of the bare `_save`
key, (b) a filter/flag to disable the mirror for host apps without
server materialization, and (c) the strip in
`deserializeBlockAttributes` reviewed alongside their private-block
-data plans (the code comment in `mergeCrdtBlocks` already envisions a
`block.private` bucket — `_save` belongs there if/when it exists).

## Open questions

1. Key name: `_save` (current) vs a namespaced constant.
2. Should the mirror also refresh on BLOCK NAME changes (transforms)?
   Transforms replace the block in practice (new Y.Block → fresh
   mirror), so this appears covered; flagging for review.
3. Containers: the mirror renders with empty inner blocks by design
   (the engine splits it around the child slots). Nested-group e2e and
   the round-trip suite stay green; worth a second pair of eyes on
   exotic container types.

## Recommended disposition (integration review, 2026-08-20 — pending human sign-off)

**Accept.** Tweak applied on `loop/integration`: the `_save` key is
hoisted to an exported `CRDT_BLOCK_SAVE_KEY` constant in
`crdt-blocks.ts`, so an upstream rename is mechanical (only the two
TypeScript interface fields repeat the literal, and the compiler ties
those). Open questions resolved as: keep the `_save` name for now
(rename is one constant away); transforms are covered by construction
(a new Y.Block always mints a fresh mirror); container edge cases
accepted on the round-trip suite's evidence.
